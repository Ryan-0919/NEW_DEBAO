## 🎯 划线标注说明

### 1. 标注级别

**每个小问都有独立的标注和总评**

```
大题（主观题）
├── 小问1
│   ├── 答案标注（answerMarks）← 划线在这里
│   ├── 遗漏要点（missedPoints）
│   └── 总评（reviewComment）← 每个小问一个总评
├── 小问2
│   ├── 答案标注（answerMarks）← 划线在这里
│   ├── 遗漏要点（missedPoints）
│   └── 总评（reviewComment）← 每个小问一个总评
└── 小问3
    ├── 答案标注（answerMarks）← 划线在这里
    ├── 遗漏要点（missedPoints）
    └── 总评（reviewComment）← 每个小问一个总评
```

## 📋 划线是怎么划的

### 流程说明

#### 阶段1：确定标注（核心批改）

AI分析答案，确定：
1. 哪些地方答对了 → `status: "score"`
2. 哪些地方答错了 → `status: "wrong"`
3. 哪些地方遗漏了 → `status: "missing"`

生成标注列表：
```json
{
  "answerMarks": [
    {"id": "m1", "status": "score", "comment": "结论正确"},
    {"id": "m2", "status": "wrong", "comment": "理由过简"}
  ]
}
```

**注意**：阶段1只确定**标注的类型和评价**，还没有确定**划在哪里**。

#### 阶段2：确定划线位置（补充信息）

AI根据阶段1的标注，在学生答案中找到对应的文本：

```json
{
  "answerMarkHighlights": [
    {
      "id": "m1",
      "highlight": "陈某提起的自诉属于法定自诉案件范围"
    },
    {
      "id": "m2", 
      "highlight": "因为公安机关不予立案，陈某有证据"
    }
  ]
}
```

#### 阶段3：合并数据

系统将阶段1和阶段2的数据合并：

```json
{
  "answerMarks": [
    {
      "id": "m1",
      "status": "score",
      "score": 2,
      "comment": "结论正确",
      "highlight": "陈某提起的自诉属于法定自诉案件范围" ← 合并后
    },
    {
      "id": "m2",
      "status": "wrong",
      "score": 0,
      "comment": "理由过简",
      "highlight": "因为公安机关不予立案，陈某有证据" ← 合并后
    }
  ]
}
```

## 🎨 前端如何渲染划线

### 1. 渲染逻辑

前端组件 `AnnotatedAnswerText` 的工作流程：

```javascript
1. 接收学生答案原文
2. 接收 answerMarks 数组
3. 遍历每个 answerMark：
   - 在答案中查找 highlight 文本
   - 根据 status 决定颜色：
     * status: "score" → 绿色背景
     * status: "wrong" → 红色背景
     * status: "missing" → 橙色背景
   - 添加批注浮窗（显示 comment + score）
```

### 2. 渲染示例

**原始答案**：
```
陈某提起的自诉属于法定自诉案件范围。因为公安机关不予立案，陈某有证据。
```

**渲染后**：
```
┌────────────────────────────────────────────────────────┐
│ [✅ 陈某提起的自诉属于法定自诉案件范围]                 │ ← 绿色背景
│    💬 结论正确 (+2分)                                   │ ← 批注浮窗
│                                                        │
│ 。[❌ 因为公安机关不予立案，陈某有证据]。              │ ← 红色背景
│    💬 理由过简 (0分)                                    │ ← 批注浮窗
└────────────────────────────────────────────────────────┘
```

### 3. 颜色规则

| status | 颜色 | 图标 | 含义 |
|--------|------|------|------|
| `"score"` | 🟢 绿色背景 | ✓ | 得分点，答对了 |
| `"wrong"` | 🔴 红色背景 | ✗ | 错误点，答错了 |
| `"missing"` | 🟠 橙色背景 | ⚠️ | 遗漏点，没答到 |

## 📝 总评（reviewComment）说明

### 1. 每个小问一个总评

**是的！每个小问都有独立的总评（300-400字）**

```json
{
  "subQuestions": [
    {
      "id": "sub_1",
      "reviewComment": "你这道题答得还不错...",  ← 第1问的总评
      "answerMarks": [...]
    },
    {
      "id": "sub_2",
      "reviewComment": "你第2问做得很好...",  ← 第2问的总评
      "answerMarks": [...]
    },
    {
      "id": "sub_3",
      "reviewComment": "第3问有点可惜...",  ← 第3问的总评
      "answerMarks": [...]
    }
  ]
}
```

### 2. 总评内容结构

每个小问的总评包含：

#### 第1部分：开头肯定（约100字）
```
你这道题答得还不错，基本方向是对的。你能够准确判断出陈某提起的自诉
属于法定自诉案件的范围，这个结论是正确的，说明你对自诉案件的基本概
念有一定的理解。
```

#### 第2部分：指出问题（约300字）⭐ 重点
```
不过咱们来看看问题在哪里。你的答案太简略了，理由部分缺乏具体的法律
分析。首先，你只说了【陈某有证据】，但没有说清楚这个证据是证明什么
的——应该明确指出是【有证据证明被告人侵犯人身权利】，这是法定要件
之一...
```

#### 第3部分：说明遗漏（约150字）
```
除了上面说的问题，你还遗漏了一个重要的采分点。你需要明确指出本案符
合【公诉转自诉案件条件】这个结论，并且最好能简单概括一下什么是公诉
转自诉案件...
```

#### 第4部分：给出建议（约100字）
```
下次遇到这类题目，建议你按照【结论+理由+具体分析】的结构来答。先给
出明确结论，再分条列出法律依据和案件事实的对应关系，最后总结为什么
符合条件。继续加油，你的基础不错！
```

### 3. 总评的作用

| 作用 | 说明 |
|------|------|
| **整体评价** | 告诉学生这个小问整体答得怎么样 |
| **详细分析** | 解释为什么扣分，哪里需要改进 |
| **具体指导** | 告诉学生正确答案应该是什么 |
| **学习建议** | 给出答题技巧和改进方法 |
| **心理鼓励** | 鼓励学生，保持学习积极性 |

## 🔗 划线与总评的关系

### 关系图

```
小问1
├── answerMarks（划线标注）
│   ├── m1: "结论正确" ✅ 
│   ├── m2: "提到证据" ✅
│   ├── m3: "理由过简" ❌  ← 局部批注（3-4字）
│   └── m4: "缺要件分析" ❌
│
└── reviewComment（总评）
    └── 643字详细说明  ← 总体批注（300-400字）

        ├── 为什么 m3、m4 扣分
        ├── 详细解释错在哪里

```

### 区别说明

| 项目 | 局部批注（comment） | 总体批注（reviewComment） |
|------|---------------------|--------------------------|
| **位置** | answerMarks 中 | 小问根级别 |
| **数量** | 每个标注一个 | 每个小问一个 |
| **长度** | 3-4字 | 300-400字 |
| **内容** | 简短标注 | 详细分析 |
| **作用** | 标记得失分点 | 整体评价+具体指导 |

## ❓ 常见问题

### Q1: 如果一个小问有多个段落，划线会跨段落吗？

**答**：会的。`highlight` 字段是从学生答案原文中提取的文本片段，可以跨段落。

### Q2: 如果highlight太长怎么办？

**答**：系统会限制highlight长度在5-30字之间，如果学生写的某个要点很长，AI会提取核心部分。

### Q3: 一个小问最多有多少个标注？

**答**：没有固定限制，通常3-6个，根据答案长度和复杂度动态调整。

### Q4: 总评一定是300-400字吗？

**答**：目标是300-400字，实际可能略有超出（如本次测试643字），但不会少于300字。

### Q5: 如果学生没作答，还会有总评吗？

**答**：会的。AI会生成类似"这道题你完全没有作答，很可惜..."的总评，告诉学生应该怎么答。

## 📊 总结

### 核心要点

1. ✅ **每个小问都有独立的标注和总评**
2. ✅ **划线通过highlight字段指定位置**
3. ✅ **总评是300-400字的详细分析**
4. ✅ **局部批注（comment）简短，总评（reviewComment）详细**
5. ✅ **前端通过AnnotatedAnswerText组件渲染划线**

### 数据流

```
学生答案
    ↓
AI批改（阶段1）→ answerMarks（标注类型）
    ↓
AI批改（阶段2）→ answerMarkHighlights（划线位置）
    ↓
数据合并 → 完整的answerMarks（类型+位置+评价）
    ↓
前端渲染 → 答案高亮 + 批注浮窗 + 总评展示
```
